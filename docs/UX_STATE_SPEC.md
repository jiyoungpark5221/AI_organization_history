# UX 상태명세서 — 기관 연혁·업무 변동 승인 도구

- 기준: 현재 코드(`app/web.py`, `app/templates/*.html`)와 가상 예시 데이터(`sample_data/`)로 실제 응답을 확인한 결과.
- 참고: 「AI 서비스를 서비스답게 만드는 UX」(강연 자료). 15~19쪽 네 가지 결함과 수정 방향, 20쪽 예외 상태 6종, 21쪽 상태명세서·QA 시트.
- 원칙(이 문서의 모든 개선안에 적용)
  - AI 결과는 언제나 **후보(제안)**이며, 확정은 **담당자 승인**으로만 이루어진다.
  - 엑셀 가져오기 자료의 상태(`CONFIRMED_*`, `Canonical` 등)는 **원천 기재**이며 이 시스템의 승인처럼 보이게 하지 않는다.
  - 날짜가 없거나 확인되지 않으면 **'미확인'**으로 쓰고 추정하지 않는다.
  - PRD 범위를 넓히지 않는다. 새 기능·DB 변경이 필요한 제안은 맨 끝 **'범위 밖 참고'**로 분리했다.
  - 승인 되돌리기 기능은 없다. 피드백은 "보류는 다시 처리할 수 있음", "수정 입력 보존", "처리 이력"으로 준다.
- 우선순위: **상** = 사용자가 잘못 판단하거나 입력을 잃는 문제, **중** = 다음 행동을 모르는 문제, **하** = 다듬기.

| 처리 결과 알림 | 상세 상단 `alert ok`/`alert` (쿼리 문자열 기반) | 결과가 상단에 떠서 아래쪽 후보 카드를 보고 있으면 놓침 | 해당 후보 카드 안(앵커 위치)에도 같은 결과를 표시 | 중 |

## 8. 상세 화면 근거표 열 구성 초안 (강연 17쪽 '조건 일치 매트릭스' 대응)

후보 카드마다 한 표. 행 = 제안 항목.

| 항목 | AI 제안 | 근거 (자료 · 조항 · 발췌) | 확인 상태 |
|---|---|---|---|
| 출발 → 도착 기관 | 가상정보화국(G2000) → 가상디지털국(G2100) | 가상정부 직제(개편 후) 제5조 · "…" | 근거 있음 |
| 관계 유형 / 이동 업무 | 승계 / 청사 정보시스템 운영 | 동 제5조 발췌 · 판단 이유 | 근거 있음 |
| 이동 범위 (업무 이동만) | 전체 / 일부 / 범위 미확인 | 근거 조항 또는 "근거 없음" | 근거 없으면 '범위 미확인' |
| 적용일 | 2026-10-02 또는 미확인 | 부칙 제1조(시행일) · 개편 후 시행일 | 확인 / 미확인 / 원천 충돌 (충돌이면 두 값 병기) |

- '확인 상태' 열 값은 기존 데이터에서만 만든다: 날짜는 `date_status`, 나머지는 해당 근거 연결 여부. 새 점수·적합도는 만들지 않는다.
- 근거가 한 건도 없으면 표 대신 "연결된 근거가 없습니다."를 유지한다(근거 없는 업무 이동은 애초에 생성되지 않음).
- 원문은 지금처럼 행 아래 접기로 둔다.

## 9. 4단계 진행바 초안 (강연 17쪽 '4단계 진행 바' 대응)

`변경 탐지 → AI 분석 → 담당자 검토 → 확정 저장`

| 단계 | 완료 | 진행 중 | 문제(경고 색) |
|---|---|---|---|
| 1 변경 탐지 | 검토 건이 존재하면 항상 완료 | — | — |
| 2 AI 분석 | `analysis_status='완료'` | `대기`, `분석 중` | `실패` → "분석 실패(재시도 대기)". `data_status='자료 부족'`·`'원천 충돌'`이면 완료 표시 옆 경고 배지 |
| 3 담당자 검토 | 모든 후보가 `승인 완료`/`기각` | 후보 중 `승인 대기`/`보류`가 있음(남은 수 표시: "3건 중 1건 남음") | 후보 0건 → "후보 없음" |
| 4 확정 저장 | 후보 중 하나 이상 `승인 완료` | — | 모든 후보 기각 → "확정 없음(기각)" |

- 목록 화면은 축약형(점 4개 + 현재 단계명), 상세 화면은 전체형.
- 진행바는 기존 컬럼만 읽는다(DB 변경 없음).
