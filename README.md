# 기관 연혁·업무 변동 자동분석 및 승인 도구

PRD: [PRD_기관연혁_자동분석_승인도구.md](PRD_기관연혁_자동분석_승인도구.md) · 개발 계획: [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)

GCC·법제처·내부 LLM의 실제 연결 방식은 아직 확인되지 않았다. 지금은 `sample_data/`의 **가상 예시 데이터**를
파일 어댑터로 읽어 수집 → 변경 탐지 → 분석 → 승인 → DB 저장 → CSV 까지 시험한다. 모든 화면은 로그인이 필요하며 승인자·수정자는 로그인 계정의 고정 사용자ID로 자동 기록된다.

## 준비

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install -r requirements.txt
```

## 로그인과 첫 계정

화면·CSV·설정은 모두 로그인 후에만 열린다. 계정 관리 화면은 없고 명령줄로 만든다. 비밀번호는 명령행 인자로 받지 않고 프롬프트로 입력한다(8자 이상).

```powershell
# 최초 계정(첫 관리자 계정) 만들기 — 비밀번호는 프롬프트로 입력
.\.venv\Scripts\python -m app.users create <login_id> <display_name>
.\.venv\Scripts\python -m app.users set-password <login_id>
.\.venv\Scripts\python -m app.users deactivate <login_id>   # 계정은 삭제하지 않고 비활성화 (과거 승인 기록 보존)
```

- '관리자 계정'은 **일반 계정과 권한이 같은 첫 계정**을 뜻한다. 역할(권한) 관리는 만들지 않았다.
- 승인·수정 후 승인·보류·기각·정정의 처리자와 승인자는 입력칸이 아니라 로그인 계정의 `user_id`로 기록되며, CSV의 승인자 열에는 계정의 표시 이름이 나온다.
- 세션은 서명된 쿠키(HttpOnly, SameSite=Lax)이고 12시간 후 만료된다. 계정을 비활성화하면 기존 세션도 즉시 차단된다. 모든 POST는 CSRF 토큰을 검사한다.
- **세션 서명 키:** 환경변수 `APP_SECRET_KEY`를 지정하는 것을 권장한다. 지정하지 않으면 DB 폴더(`data/`)에 무작위 키 파일 `.secret_key`가 처음 한 번 만들어져 재사용된다. 키가 바뀌면 모두 로그아웃된다. 키는 저장소에 올리지 않는다(`data/`는 `.gitignore`).
- 사내 SSO·LDAP 연동 방식은 확인되지 않아 구현하지 않았다. 인증은 `app/auth.py`의 `AuthProvider` 인터페이스 뒤에 있어 확정되면 구현체를 교체한다.
- **알려진 한계:** 로그인 연속 실패 제한은 프로세스 메모리에서 로그인 ID별로 계산한다(재시작·다중 프로세스 간 공유 없음). 로그아웃은 브라우저의 쿠키를 지울 뿐 서버에 세션 목록이 없어, 탈취된 쿠키는 만료(12시간)되거나 계정이 비활성화될 때까지 유효하다. 운영 시 HTTPS(쿠키 `Secure` 자동 적용)로 서비스한다.
- **개발용 DB 재생성:** 로그인 도입으로 승인자·수정자 컬럼이 사용자ID로 바뀌었다. 이전에 만든 개발용 DB(`data/app.db`)는 마이그레이션하지 않으므로 지우고 다시 만든다.

## 실행

```powershell
# 화면 (접속 주소 http://127.0.0.1:8000 → 로그인 화면으로 이동)
.\.venv\Scripts\python -m uvicorn app.web:app --reload

# 일일 작업 (외부 스케줄러가 매일 호출). 날짜를 생략하면 오늘
.\.venv\Scripts\python -m app.daily --date 2026-10-01
.\.venv\Scripts\python -m app.daily --date 2026-10-02
```

DB 파일은 기본 `data/app.db`이며 환경변수 `APP_DB`로 바꿀 수 있다.

## 예시 데이터로 전체 흐름 시험

1. `--date 2026-10-01` 실행 → 최초 수집본이 비교 기준본이 된다(변경 0건).
2. `--date 2026-10-02` 실행 → 변경 2건(검토 건 2개)이 승인 대기로 등록된다. 법령 자료가 일부 빠진 건은 '자료 부족'으로 표시된다.
3. 로그인한 뒤 화면에서 건을 열어 근거를 확인하고 후보별로 승인 / 수정 후 승인 / 보류 / 기각한다.
4. `--date 2026-10-03` 실행 → 같은 자료이므로 변경 없음, 검토 건이 중복 생성되지 않는다.
5. 목록의 'CSV 다운로드'(`/export.csv`)로 승인된 결과를 내려받는다.

화면의 `설정 → 지금 실행`, `수동 파일 입력`으로도 같은 시험을 할 수 있다.

## 엑셀(환경부 Pilot) 가져오기 — 참고 자료 입력·매핑 시험

```powershell
.\.venv\Scripts\python -m app.import_xlsx "환경부_GCC_CAMS_기관관계업무_마스터_Pilot_v03_원자료보완.xlsx" [--db 경로]
```

- 원본 엑셀은 읽기 전용으로만 열며 수정하지 않는다(보고서에 가져오기 전후 sha256 표시).
- 02_SOURCE_MAP(기관코드·명칭·원천 날짜), 09_ORG_WORK(업무 원문), 03_ORG_RELATION(원천 연결 `SOURCE_LINK` / 검토된 관계 `CANONICAL_RELATION` 를 layer 로 구분), 01_ORG_MASTER(기관 식별용)만 가져온다. 나머지 시트는 가져오지 않는다.
- 공통기관ID(`COMMON`)와 GCC 코드를 `org_identifier`에 보존한다. 이 파일에는 OG 전거ID가 없어 `OG` 식별자는 만들지 않으며, 09의 `OG_CODE`는 `ref_org_work.og_code_raw`에 원문으로만 둔다.
- 값은 `ref_org_record` / `ref_org_work` / `ref_org_relation` 참고 테이블에 원본 상태·출처 그대로 저장한다. 파일의 `REVIEW_STATUS`·`MASTER_STATUS` 등은 `*_src` 컬럼의 원본 상태일 뿐 **우리 시스템의 승인이 아니다**. 확정 데이터·검토 이력·후보 테이블에는 쓰지 않는다.
- 같은 파일을 다시 가져와도 중복되지 않으며(멱등), 한 번의 가져오기는 하나의 트랜잭션이다.
- 가져온 건수, 연결하지 못한 코드, 미확인 날짜는 실행 후 콘솔과 `import_run.report_json`에 남는다.
- **한계:** 이 파일은 일자별 GCC 스냅샷이 아니다. `collection_run`/`gcc_record`/`change_event`를 만들지 않으며 시작·종료일로 두 시점 자료를 만들지 않는다. 실제 변경 탐지 검증에는 별도의 변경 전·후 GCC 자료가 필요하며, 이 가져오기로 검증된 것이 아니다.

## 계보도 보기 (교육 발표용)

변경 상세 화면(`/cases/<번호>`)의 **계보도 보기** 버튼을 누르면 '기능 담당 조직 계보도' 패널이 펼쳐집니다(읽기 전용, DB에 쓰지 않음). 기본은 그 건의 기관이고, 엑셀에서 가져온 기관은 패널의 **기관 검색**(이름·GCC 코드·공통기관ID, 최대 20건)으로 골라 볼 수 있습니다. 엑셀 기관을 보려면 먼저 `python -m app.import_xlsx`로 가져오고, 화면에 들어갈 검토 건이 하나는 있어야 하므로 예시 데이터로 `python -m app.daily`를 한 번 실행해 두세요.

- **세 층을 구분해서 표시:** *원천 기재*(엑셀 가져오기 · 가는 실선), *검토 후보*(AI 제안 · 점선), *승인 결과*(우리 시스템 승인 · 굵은 실선). 색뿐 아니라 텍스트 배지와 선 모양으로도 구분하며, 범례가 항상 붙습니다.
- **화살표는 승인된 업무 이동(`confirmed_task_move`, 현재 유효한 것)만:** 기관관계(상위기관·이전기관 링크·승계 관계)는 화살표 없는 선입니다. 원천·후보의 업무는 기관 상자 안에 '업무 승계 미확인' 또는 '후보(미확정)'로만 적습니다.
- **엑셀의 Canonical·확인 상태는 '원천 파일의 검토 상태 … (우리 시스템 승인 아님)'** 으로만 표시합니다.
- **날짜·OG 전거ID:** 값이 없거나 확인되지 않은 날짜는 '미확인', 기관 생성·폐지일은 '원천 관측기간(관계·업무 유효기간 아님)'으로 따로 표시합니다. OG 전거ID가 확보되지 않았으면 '미확보'이며, 엑셀의 `OG_CODE` 값은 'OG_CODE 원문'으로만 보입니다.
- 승인된 업무 이동이 없으면 '업무 승계는 확인되지 않음(연결자료 부족)'이라고 안내하고 실제 기관관계와 담당 업무까지만 보여줍니다. 한 번에 최대 16개 기관까지 표시합니다. 좁은 화면에서는 그림 대신 같은 내용을 글 목록으로 쌓아 보여줍니다.

### 두 줄 구조 (기관 단위 + 하위 조직)

엑셀에서 가져온 기관을 고르면 계보도가 줄로 나뉩니다. 위쪽 **기관 단위 계보**에는 최상위 소속 기관과 그 전·후신(예: 환경청 → 환경처 → 환경부 → 기후에너지환경부), 가운데 **중간 소속**(예: 자연보전국), 아래쪽 **하위 조직 계보**에는 선택한 기관과 그 전·후신이 나옵니다. 소속은 GCC 상위기관 링크가 있는 곳만 선으로 잇고, 엑셀에 소속 자료가 없는 기관(예: 코드 없는 환경처 시절 자연정책과)은 선을 잇지 않고 **소속 연결 미확인**으로 표시합니다. 관계 날짜는 엑셀에 없어 모두 '미확인'이며, CAMS 기간은 '원천 관측기간'으로만 표시합니다.

## 교육 시연 (시연용 가정 데이터)

엑셀 기관만으로는 승인된 업무 이동이 없어 계보도에 화살표가 나오지 않습니다(정상). 발표에서 **원천 기재 → 검토 후보 → 승인 결과**로 바뀌는 과정을 보여주려면, 운영 DB와 분리된 시연 전용 DB를 만듭니다.

> **경고:** 시연 후보 2건(자연정책과 → 자연생태정책과, 환경처 → 환경부)은 **교육 시연용 가정이며 엑셀에서 확인된 사실이 아닙니다.** 엑셀의 업무 승계는 전부 미확인입니다. 업무 내용은 엑셀 원문을 그대로 인용했을 뿐이고, 해당 업무가 실제로 이동했다는 뜻이 아닙니다.

```powershell
# 1) 시연 DB 만들기 (승인 대기 상태. 운영 DB 경로는 거부됨. 이미 있으면 --reset)
.\.venv\Scripts\python -m app.demo_seed "환경부_GCC_CAMS_기관관계업무_마스터_Pilot_v03_원자료보완.xlsx" --db data/demo.db
#    비밀번호는 --password-stdin 또는 환경변수 DEMO_PASSWORD, 둘 다 없으면 무작위로 만들어 한 번만 출력합니다.
#    --approve 를 붙이면 demo 계정이 정식 승인 서비스로 두 후보를 승인해 화살표가 보이는 상태까지 만듭니다.

# 2) 시연 DB로 서버 실행
$env:APP_DB = "data/demo.db"
.\.venv\Scripts\python -m uvicorn app.web:app
# 브라우저: http://127.0.0.1:8000  → 계정 demo 로 로그인
```

발표 흐름: ① **원천 기재** — `[교육 시연용]` 건을 열고 '계보도 보기'. 화살표 없이 기관관계·업무 원문만 보이고 업무 승계는 '미확인'. ② **검토 후보** — 아래 업무 이동 후보 카드(점선·승인 대기)를 보여줌. ③ **승인 결과** — 카드에서 승인하면 계보도에 굵은 화살표가 생기고 승인자(시연 계정)·날짜 '미확인'이 표시됨. 승인 이력과 CSV에도 시연용 가정 표시가 남습니다. `--approve` 로 만들었다면 ③ 상태에서 시작합니다. 이 스크립트는 수집·변경 탐지 데이터를 만들지 않으며, 실제 변경 탐지 검증은 별도의 변경 전·후 GCC 자료가 필요합니다.

## Vercel 샘플 배포

화면을 샘플로 확인하기 위한 배포 설정이다. 운영용이 아니다.

- 진입점은 `pyproject.toml` 의 `[tool.vercel] entrypoint = "app.web:app"` 이다.
- Vercel 은 디스크가 영구 보존되지 않아 DB 를 `/tmp` 에 두고, 비어 있으면 `sample_data/` 의 가상 예시 자료로 일일 작업을 돌려 검토 건을 채운다(`app/sample_bootstrap.py`).
- **기본 샘플 계정:** Vercel 에서 환경변수를 설정하지 않으면 `admin` / `11111111` 계정이 만들어진다. 이 값은 저장소에 공개되므로 샘플 확인용으로만 쓰고, 실제 자료를 연결하기 전에는 반드시 아래 환경변수로 바꾼다. 내 PC에서 실행할 때는 기본 계정이 만들어지지 않는다.
- **로그인 계정을 직접 정하려면** Vercel 프로젝트의 Environment Variables 에 다음을 설정한다(환경변수가 있으면 기본 계정 대신 이 값이 쓰인다).

  | 변수 | 설명 |
  |---|---|
  | `SAMPLE_LOGIN_ID` | 샘플 로그인 ID |
  | `SAMPLE_PASSWORD` | 샘플 비밀번호 (두 변수가 모두 있을 때만 계정 생성) |
  | `SAMPLE_DISPLAY_NAME` | (선택) 표시 이름 |
  | `APP_SECRET_KEY` | 세션 서명 키(긴 무작위 문자열). 없으면 인스턴스마다 키가 달라 로그인이 풀릴 수 있다 |

- **한계:** 승인 결과·계정은 인스턴스가 바뀌거나 콜드 스타트되면 사라진다(`/tmp` 는 임시 저장소). 일일 수집 스케줄러도 돌지 않는다. 데이터가 유지되어야 하는 실제 사용은 영구 디스크가 있는 서버에서 해야 한다.
- 엑셀 원본은 저장소와 배포에 포함하지 않으므로, 배포본의 계보도는 엑셀 기관 없이 샘플 건의 기관만 보여준다.
